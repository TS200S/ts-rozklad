# TS Розклад V5.2.6 — CSP + керування сесіями

## Що додано
- CSP та базові security headers через Netlify.
- `HttpOnly` cookie залишається єдиним способом передачі сесії.
- У налаштуваннях акаунта є «Активні сесії та пристрої».
- Перегляд активних сесій без розкриття session token.
- Завершення окремої сесії.
- Завершення всіх інших сесій одним підтвердженням.
- Поточну сесію не можна завершити з менеджера; для цього використовується звичайний вихід.
- Для ідентифікації сесії UI бачить лише короткий непрямий `sessionId` (hash-prefix), а не cookie/token.

## CSP
Через існуючу архітектуру з великим inline JavaScript/CSS CSP використовує `script-src 'unsafe-inline'` і `style-src 'unsafe-inline'`. Це покращує поверхневий захист від небезпечних ресурсів, але не є максимально суворою CSP.

Наступний рівень — винести inline JS/CSS або перейти на nonce/hash-based CSP.
