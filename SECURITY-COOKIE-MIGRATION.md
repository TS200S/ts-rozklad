# V5.2.5 — HttpOnly Session Cookie

Сессионный токен приложения больше не хранится в `localStorage` и не принимается из `Authorization: Bearer`.

## Как работает

- После успешного входа сервер выставляет `__Host-ts_session`.
- Cookie имеет `Secure; HttpOnly; SameSite=Lax; Path=/`.
- Префикс `__Host-` запрещает задавать Domain и требует Secure + Path=/.
- JavaScript не может прочитать cookie.
- API извлекает сессию только из cookie.
- `X-TS-Device-ID` остаётся отдельным идентификатором устройства и не является секретом.
- Сервер по-прежнему сверяет deviceId + User-Agent для защиты от повторного использования украденной сессии.
- При выходе cookie очищается сервером.

## Миграция

После развёртывания V5.2.5 старые bearer-токены из предыдущих версий больше не принимаются. Пользователям достаточно войти заново.

Это намеренно: старый токен не должен становиться альтернативным способом авторизации после перехода на HttpOnly cookie.

## Почему это безопаснее

Даже если XSS-скрипт выполнится в странице, `document.cookie` не сможет прочитать `__Host-ts_session`. Сессионный секрет остаётся доступен браузеру для отправки на тот же сайт, но не JavaScript-коду.

Дополнительная привязка к `X-TS-Device-ID` + User-Agent продолжает работать как второй слой защиты от replay.
